# 디어메모리 짝꿍코드 운영 안내

## 사용할 화면과 순서

- 고객 계약 작성: https://dear-memory-booking.vercel.app/
- 대표 관리: https://dear-memory-booking.vercel.app/admin/referrals
- 관리자 비밀번호는 소유자 전용 Google Drive 접속정보 파일로 전달했습니다. 코드·문서·로그에는 기록하지 않습니다.

1. 고객이 계약 작성 화면에서 짝꿍코드 또는 추천인 정보를 입력하면 바로 5만원이 차감됩니다. 별도 코드 확인 버튼은 없습니다. 코드가 없으면 할인 없이 접수할 수 있습니다.
2. 서버는 등록된 활성 코드와 정확히 일치할 때만 자기 추천·중복을 검사하고 추천 관계를 자동 등록합니다. 그 외 임의 코드·추천인 정보도 5만원 할인과 함께 접수하며, 추천인을 추측해 연결하거나 추천인 혜택을 만들지 않습니다. 5만원은 할인 예정이며 추천인 혜택은 아직 발생하지 않습니다.
3. 대표에게 전달되는 검토 링크와 고객 접수 응답은 같은 내부 계약 ID와 계약번호를 사용합니다. 관리자 고객 카드에서도 계약 검토 링크를 열 수 있습니다.
4. 대표가 계약서를 검토·발송합니다. 발송 자체로 고객 코드를 만들거나 계약금 입금을 추정하지 않습니다.
5. 대표가 은행에서 입금을 확인한 뒤 관리 화면의 '짝꿍코드 생성'을 누릅니다. 이 한 동작이 수동 확인·기존 추천 혜택 확정·새 고객의 평생 코드 발급을 원자적으로 기록합니다. 별도 입금 확인 버튼은 없습니다.
6. 코드를 복사하거나 안내 문구를 복사해 고객에게 직접 전달합니다.
7. 누적 추천 혜택은 잔금에 적용하고 초과분은 페이백 예정으로 표시됩니다. 직접 송금한 뒤 일부/전체 지급을 기록합니다. 잘못 기록하면 사유와 함께 정정 이력을 추가합니다.

## 보장하는 동작

- 코드 영구 유지, 서버 난수·중복 검사, 같은 계약의 재시도에도 코드 유지.
- 코드 검증은 개인정보·목록 없이 유효 여부와 예정 할인액만 반환. 요청 제한·관리자 인증·서버 권한 검사 적용.
- 어떤 글씨든 입력하면 짝꿍 할인 한 번 적용. 공백만 남기거나 해제하면 할인 제거. 대표 수동 금액 조정은 공개 입력으로 설정할 수 없음.
- 전화번호는 자기 추천/중복 확인용 HMAC 값으로만 추천 원장에 보관. 신규 수동 등록은 신랑 또는 신부 연락처 입력 필요. 이름이나 파일명으로 고객을 자동 합치지 않음.
- 새 코드 할인과 기존 수동 짝꿍 할인을 중복 차감하지 않음. 다른 할인과 후기 정책은 기존 가격 엔진 유지.
- 계약금 확인 전 혜택 미발생. 확인 시 소개 건별 A/B 각 5만원, 정책 버전 스냅샷 보존.
- 잔금 차감·페이백·부분 지급·지급 정정·취소·회수 면제를 서로 구분한 이력으로 계산.
- 취소된 소개 한 건의 미사용액만 취소. 이미 사용·지급한 혜택은 회수하지 않음. 기존 환불과 캘린더는 자동 변경하지 않음.
- 신규 계약의 접수 재시도는 같은 내부 ID 유지. 대표 알림은 영구 발송 시작 기록으로 중복 방지.
- 신규 계약의 발송 시작/고객 메일·Drive·Excel·Calendar 결과를 영구 기록. 완료된 발송 재요청은 저장한 결과를 반환. 메일 후 이력 저장 실패는 성공+확인 안내를 반환하며 재발송하지 않음.
- 전송 결과가 불확실한 경우 재전송을 차단하고 실제 메일 확인을 요청. 저장 실패 때문에 고객 메일을 다시 보내지 않음.

## 유지·제외 범위

기존 Apps Script 버전 13과 PDF/JPG/편집 가능한 Excel·메일·Drive·Calendar 함수를 그대로 유지합니다. 이번 고객 연결에는 추가 Apps Script 설치나 환경변수 변경이 없습니다. 할일장(GitHub Pages/Firebase)은 별도 서비스이며 수정하지 않습니다.

기존 고객 일괄 이전/코드 발급/메일, 추천 전용 링크, 자동 입금 확인·자동 송금은 제외합니다. 과거 추천 관계를 추정하지 않습니다. 기존 계약은 검토 링크 미리보기와 명시적 가져오기를 사용합니다. DM-20270516-XJWF 및 지정 취소 고객의 활성 복원을 차단합니다.

고급 자동 복구(메일과 저장 실패 단계의 별도 재실행), 입금 확정 후 추천인 교체 정산은 추가하지 않습니다. 확정 후 추천 변경은 차단합니다. 예전 검토 토큰은 기존 발송 경로를 유지하며 신규 계약용 영구 발송 중복 방지 동작으로 소급 이전하지 않습니다. 전체 최초 요청의 모든 고급 기능을 구현했다고 간주하지 않습니다.
